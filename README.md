# Lap Logger（本庄サーキット用 走行ロガー＆分析）

スマホのブラウザだけで動く、GPS とスマホのセンサーを使った走行データロガーと分析ツールです。
インストール不要の Web アプリ（PWA）で、ホーム画面に追加すればアプリのように使えます。データは端末の中だけに保存されます。

RaceChrono / Harry's LapTimer / AiM / VBOX Circuit Tools / Garmin Catalyst など定番ロガーの機能を参考にしています。

## できること

### 計測（走行中）
- **予測タイム差（デルタ）**: 自己ベストと比べて今どれだけ速い・遅いかを大きく表示（緑＝速い / 赤＝遅い）。予測ラップタイムも表示
- 現在ラップ・前周・ベスト・速度・G メーター・直近ラップ一覧。画面は常に暗い配色（車内で見やすい）、横向きにも対応
- **初めてのコースでも自動**: 1周走るとコースを覚えて S/F ラインを自動で設定し、2周目からラップを計測
- ラップタイムの**音声読み上げ**（「48秒52、プラス0.4」「自己ベスト更新」など）とバイブ
- 記録するデータ: GPS（位置・ドップラー速度・方位・高度・精度）、加速度（重力込み）、ジャイロ（回転速度）を 25Hz で
- 誤操作を防ぐ**長押しで停止**、画面点灯の維持、10秒ごとの自動保存（途中で落ちてもデータは残る）
- 車両・タイヤ・空気圧・天気・気温・路面・セットアップ・メモを記録（前回の内容を引き継ぎ）

### 分析（走行後）
| タブ | 内容 |
|---|---|
| 概要 | ベスト / **理論ベスト**（区間ベストの合計）/ 安定度 / 最高速 / 最大減速G / 最大横G / 自己ベスト、ラップタイム棒グラフ、**タイムを縮められる場所 TOP3**（「ブレーキ開始が 7m 奥」「最低速度 +3km/h」など具体的に）、加速・ブレーキ・どちらでもない時間の割合、50→100km/h 加速・100→50km/h 減速性能、データの品質 |
| ラップ | **スプリット表**（コーナーごとの区間タイム。紫＝全ラップ中の最速）、コーナーごとのばらつき（最低速度・ブレーキ開始位置） |
| コース | **コース図**（走行データから作ったコース面・コーナー番号・S/F・縁石・距離目盛り）に基準/比較ラップのラインを重ねる。色分け: 速度 / ブレーキ・加速 / 横G / タイム差。ブレーキ開始・アクセルON・最低速度の位置。**リプレイ**（2台を同時に走らせる）。**ライン位置**グラフ（コースのどこを走ったか）。航空写真表示 |
| グラフ | 速度・タイム差・前後G・横G・ライン位置・合成G・経過時間・標高を**コース上の距離**でそろえて重ね表示。コーナー区間の帯、なぞるとコース図の位置と連動、2本指でズーム |
| コーナー | コーナーごとの拡大図と指標: 区間タイム・ブレーキ開始位置（頂点までの距離）・進入速度・最大減速・最低速度・クリップ位置（インまでの距離）・アクセルON・立ち上がり速度・最大横G。基準と比較の差 |
| G-G | 摩擦円（G-G ダイアグラム）、グリップ使用率、ラップ別の走り方 |

- **別の日のセッションとも比較**できます（比較ラップの選択肢に「他のセッションのベストラップ」）。日によって GPS が数 m ずれても自動で補正します
- 書き出し: 解析データ CSV（ラップ×距離ごとの速度・G・ライン）、ラップ表 CSV、KML（Google Earth）、GPX、生データ CSV、JSON。スマホでは共有メニューから送れます

### 読み込み
本アプリの JSON / CSV、GPX、NMEA（RMC + GGA）、VBO（VBOX）、緯度・経度・時刻を含む一般的な CSV（RaceChrono・AiM などの書き出し。単位行も解釈）。
10Hz 以上の外部 GPS ロガーのデータを読み込めば、より細かく分析できます。

## コース形状の作り方（「どこを走ったか」の分析）

1. 最速ラップの軌跡を出発点に、全ラップのラインを平均して**基準ライン**（コースの形）を作ります。1Hz の GPS でも周回を重ねるほど正確になります
2. 各ラップの点を基準ラインに投影して「**コース上の距離**（S/F から何 m）」と「**横位置**（基準ラインから右に何 m）」に変換します。これで速さの違うラップや別の日のラップを同じ地点どうしで比べられます
3. 全ラップの横位置の範囲を「走行範囲（推定コース面）」として描き、曲率からコーナーを自動検出して T1, T2… と番号を付けます（名前は設定で変更可）
4. コース形状は保存され、次のセッションからは同じ距離軸・同じコーナー番号で比較できます。新しいセッションのデータで少しずつ更新されます
5. 設定から OpenStreetMap のサーキット形状を取得して重ねて表示することもできます（地図に登録されている場合）

## 精度（デモデータの正解値と比べたテスト結果・スマホ GPS 1Hz 相当）

`node test/run.mjs` で、正解が分かっている疑似走行データと比べて検証しています。

| 項目 | 結果 |
|---|---|
| ラップタイム | 誤差 ±0.1 秒程度（RMS）。GPS 位置誤差（約2m）によるもので、ノイズがなければ 0.02 秒未満 |
| 速度 | 加速度センサーで GPS の間を補完すると RMS 誤差 0.7 km/h（補完なし 3.0 km/h）。最高速の取りこぼしも −5.5 → −1.3 km/h に改善 |
| 横G | ジャイロ × 速度で RMS 誤差 0.07G（GPS の方位だけだと 0.23G） |
| ブレーキ開始位置 | 平均 −1.7m、RMS 3.8m（センサーあり） |
| コース形状 | 長さの誤差 1% 以内、コーナーの数と向きを検出 |
| 横位置（ライン） | ラップ間の差の誤差 約1m。1m 未満の違いは誤差の範囲。大きなライン変化やミス（膨らみ）の確認向き |

スマホの取り付け向きはどの方向でも構いません。重力の方向・前方向・ジャイロの単位と符号は走行データから自動で推定します。

## 使い方（サーキット当日）

1. スマホで公開 URL（下記）を開き、**ホーム画面に追加**。一度開けば圏外でも起動できます（地図の背景写真は見たことのある範囲だけ）
2. 「計測」タブでセッション情報（車両・タイヤ・空気圧など）を入力
3. スマホをホルダーでしっかり固定。「GPS の受信状態を確認」で精度が 5m 以下になるまで待つ
4. 「記録開始」→ 位置情報と（iPhone は）モーションセンサーへのアクセスを許可
5. **記録中は画面を点けたまま、アプリを前面に**（画面を消すと多くの端末で GPS が止まります。自動ロックはオフに。充電しながらがおすすめ）
6. 走り終わったら停止ボタンを**長押し** → そのまま分析画面が開きます
7. S/F ラインの位置は「コース」タブの「S/F 設定」で地図をタップして直せます（セクターも同様）

## 公開方法（GitHub Pages）

位置情報を使うには HTTPS での配信が必要です。

1. このブランチを `main` にマージする
2. GitHub のリポジトリで **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にする
3. `main` に push すると `.github/workflows/pages.yml` がテストを実行してから公開します。URL は `https://<ユーザー名>.github.io/<リポジトリ名>/`

## 開発

ビルド不要の素の HTML / JavaScript（ES Modules）です。

```
js/core.js       信号処理: エルミート補間（GPS 速度ベクトル利用）、センサー融合（重力・前方向・ジャイロの自動推定）、速度補完、周回検出
js/track.js      コースモデル: 基準ライン作成・統合、投影（距離・横位置）、GPS ずれ補正、コーナー検出、予測ラップ用の基準
js/analysis.js   解析: ラップの距離そろえ、コーナー指標、区間タイム・理論ベスト、改善ポイント、加速・減速性能
js/io.js         読み込み（CSV/GPX/NMEA/VBO）と書き出し（CSV/解析CSV/ラップ表/GPX/KML）
js/demo.js       デモ用の疑似走行データ（架空コース・正解値つき）
js/store.js      保存（IndexedDB / localStorage）
js/ui/*.js       画面（計測・セッション・分析・設定）、コース図、グラフ
sw.js            オフライン対応
```

- テスト: `node test/run.mjs`（解析ロジック 17 項目）
- 画面の確認: ローカルの HTTP サーバーで配信してブラウザで開く（例: `python3 -m http.server`）。「セッション → デモデータ」で分析画面を試せます
